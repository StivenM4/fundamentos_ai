Paso 3: Notificar al usuario formalmente sobre la violación de las políticas de uso aceptable de tecnología. Paso 4: Proceder con la desinstalación silenciosa del aplicativo mediante PowerShell: Uninstall-Package o msiexec /x. Paso 5: Generar el informe de cumplimiento de licencias para el departamento jurídico y de auditoría interna.
Resolución de conflictos de versiones de Java Runtime Environment (JRE) en portales bancarios: Paso 1: Si un aplicativo bancario o gubernamental no abre y exige una versión específica obsoleta de Java (ej. Java 8 update 202). Paso 2: Abrir el Panel de Control de Java > pestaña Java > botón Ver para listar las versiones JRE instaladas en el sistema. Paso 3: En la pestaña Seguridad, agregar la URL exacta del portal bancario en la Lista de excepciones de sitios. Paso 4: En la pestaña Avanzadas, asegurarse de tener habilitados los protocolos TLS 1.2 y TLS 1.3. Paso 5: Si el navegador predeterminado bloquea los applets de Java, configurar el modo IE (Internet Explorer Mode) en Microsoft Edge.
Diagnóstico de fallos en generación y firma de archivos XML de nómina electrónica hacia DIAN: Paso 1: Si el software de gestión de talento humano arroja rechazo en el envío del lote de nómina electrónica a los servidores de la DIAN. Paso 2: Abrir el archivo XML generado y validarlo contra el esquema XSD oficial de la DIAN utilizando un validador XML. Paso 3: Comprobar que los campos de identificación del empleado (tipo documento, cédula, nombre) no contengan caracteres especiales no permitidos. Paso 4: Verificar que el certificado digital de nómina electrónica no haya expirado y esté correctamente firmado con el algoritmo SHA-256. Paso 5: Reenviar el documento de soporte de nómina corregido y verificar la recepción del código único de documento (CUNE) con estado Aceptado.
Corrección de fallos en videollamadas de Microsoft Teams por códecs y aceleración gráfica: Paso 1: Si durante las reuniones de Teams la pantalla parpadea en negro o los demás participantes no escuchan el audio del expositor. Paso 2: En Teams, hacer clic en Configuración (...) > General y marcar Deshabilitar aceleración de hardware de GPU. Paso 3: En Configuración > Dispositivos, desactivar Supresión de ruido si la CPU del equipo es de baja potencia para liberar ciclos de procesamiento. Paso 4: Purgar la caché de Teams cerrando la aplicación y eliminando los contenidos de %appdata%\Microsoft\Teams\Cache. Paso 5: Reiniciar Microsoft Teams y efectuar una llamada de prueba para corroborar estabilidad de video a 30 fps.
Procedimiento de compactación y purga de buzones de correo para usuarios al límite de cuota: Paso 1: Si el usuario recibe avisos de Su buzón está casi lleno y no puede enviar nuevos correos por superar los 50 GB / 100 GB. Paso 2: En Outlook, abrir Archivo > Herramientas > Limpieza de buzón e identificar elementos de gran tamaño mayores a 10 MB. Paso 3: Vaciar de forma definitiva la carpeta Elementos eliminados y la carpeta Correo no deseado. Paso 4: Configurar directiva de retención o archivado en línea (Online Archive) en Microsoft 365 para mover correos de más de 2 años al archivo histórico ilimitado. Paso 5: Para clientes IMAP/POP locales, exportar elementos antiguos a un archivo de datos PST local seguro y compactar el buzón.
Verificación de integridad y restauración de consistencia en bases de datos con DBCC CHECKDB: Paso 1: Si el motor de base de datos reporta errores de I/O, páginas dañadas (torn pages) o inconsistencias lógicas en índices. Paso 2: En SQL Server Management Studio, programar una ventana de mantenimiento y ejecutar DBCC CHECKDB ('<NombreBD>') WITH NO_INFOMSGS. Paso 3: Si se detectan errores de consistencia en tablas de usuario, evaluar el nivel mínimo de reparación sugerido. Paso 4: Si se sugiere REPAIR_REBUILD, poner la base de datos en modo monousuario y ejecutar DBCC CHECKDB ('<NombreBD>', REPAIR_REBUILD). Paso 5: Si se requiere REPAIR_ALLOW_DATA_LOSS, detener la operación de inmediato y proceder con la restauración desde el último respaldo limpio.
Procedimiento de actualización de firmware y agentes SNMP en servidores físicos y switches: Paso 1: Descargar el paquete de actualización de firmware certificado por el fabricante y verificar el checksum SHA-256 oficial. Paso 2: Verificar la compatibilidad de versiones con el hardware actual y comprobar que no existan dependencias de saltos intermedios de versión. Paso 3: Programar ventana de mantenimiento en horario no laboral notificando a los administradores de sistemas. Paso 4: Conectar el servidor o switch a una UPS con respaldo garantizado para impedir cortes eléctricos durante el flasheo de la memoria ROM. Paso 5: Aplicar la actualización mediante la interfaz web de gestión o consola CLI, esperar el reinicio automático y verificar la versión operativa.
Reparación de perfil de usuario corrupto de Windows que inicia con cuenta temporal TEMP: Paso 1: Si al iniciar sesión el usuario observa un escritorio vacío con fondo negro y el aviso Ha iniciado sesión con un perfil temporal. Paso 2: Iniciar sesión con una cuenta de administrador local para no alterar el perfil del usuario. Paso 3: Abrir regedit y navegar a HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList. Paso 4: Localizar la clave del SID del usuario que tiene la extensión .bak y la clave homónima sin extensión. Paso 5: Renombrar la clave sin extensión a .corrupt y retirar la extensión .bak de la clave original; verificar que ProfileImagePath apunte a C:\Users\<Usuario> y reiniciar.
Configuración y verificación de scripts de inicio de sesión (logon scripts) en Sysvol de dominio: Paso 1: Si las unidades de red o impresoras corporativas no se asignan automáticamente al iniciar sesión los usuarios. Paso 2: Acceder a la carpeta compartida \\dominio.local\SYSVOL\dominio.local\scripts y localizar el script de inicio (ej. logon.bat o logon.ps1). Paso 3: Abrir el script en un editor de texto y verificar que las rutas UNC de los servidores compartidos sigan vigentes. Paso 4: Probar la ejecución manual del script en una estación de trabajo cliente para observar si arroja errores de sintaxis o permisos. Paso 5: En la directiva de grupo (GPO), verificar que la directiva Ejecutar scripts de inicio de sesión de forma sincrónica esté habilitada.
Detección y eliminación de volcados de memoria minidump huérfanos que saturan el disco C:: Paso 1: Si el disco del sistema C: muestra espacio libre crítico menor al 5% y no se identifican archivos de usuario pesados. Paso 2: Abrir cmd como administrador y revisar el tamaño de las carpetas de diagnóstico: C:\Windows\Minidump y C:\Windows\MEMORY.DMP. Paso 3: Si se produjeron pantallas azules recurrentes, Windows puede haber acumulado gigabytes de volcados de memoria completos. Paso 4: Ejecutar la herramienta cleanmgr /sageset:1 marcando Archivos de volcado de memoria de errores del sistema y ejecutar cleanmgr /sagerun:1. Paso 5: Configurar en Propiedades del sistema > Inicio y recuperación el tipo de volcado en Volcado de memoria pequeño (256 KB).
Procedimiento para pruebas semestrales de conmutación por desastre (Disaster Recovery): Paso 1: Convocar al comité de continuidad del negocio y activar la ventana programada de simulación de desastres. Paso 2: Simular la pérdida del centro de datos principal aislando la red troncal de producción. Paso 3: En el sitio secundario o nube de contingencia, activar la réplica de máquinas virtuales mediante el orquestador de Disaster Recovery (Veeam / Azure Site Recovery). Paso 4: Validar el encendido en orden estricto de dependencias: Controladores de Dominio > Base de Datos > Servidores de Aplicación > Frontend Web. Paso 5: Ejecutar pruebas de humo funcionales con usuarios clave, documentar el RTO y RPO alcanzados y conmutar de retorno a producción.
Para errores de ejecucion en navegadores con aplicaciones web empresariales que requieren Java antiguo, instalar la version JRE homologada, anadir el sitio a la lista de excepciones de Java y fijar nivel de seguridad en alto.
Si el aplicativo de gestion documental corporativo no abre documentos PDF en el navegador, deshabilitar el visor PDF integrado de Chrome o Edge y asociar Adobe Acrobat Reader como manejador predeterminado.
Ante problemas de compatibilidad en software legado que requiere modo de compatibilidad con Windows 7, aplicar solucionador de problemas de compatibilidad de programas y configurar ejecucion como administrador.
Cuando una aplicacion cliente servidor reporta perdida de conexion tras periodos de inactividad, configurar politicas de KeepAlive en el registro de Windows para mantener abiertos los sockets TCP en sesiones remotas.
Para recuperar archivos cifrados o alterados accidentalmente en carpetas compartidas de red, restaurar el directorio afectado a partir de la copia de seguridad incremental nocturna mas reciente y auditar el origen del incidente.
